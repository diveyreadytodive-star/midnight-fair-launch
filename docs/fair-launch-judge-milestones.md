The official [browser DApp example](https://docs.midnightkorea.org/examples/dapps/leaderboard) shows DApp Connector API v4 wallet balancing and Preprod proving. The [connector specification](https://github.com/midnightntwrk/midnight-dapp-connector-api/blob/main/docs/api/_media/SPECIFICATION.md) does not expose raw shielded UTXOs to a DApp, while the current Fair Launch `registerBid` takes a `ShieldedCoinInfo` input. A plausible integration route is a wallet-signed `mintTestPaymentCoin` call whose returned coin record is then passed to `registerBid`; this is **only a hypothesis** until proven in a real browser wallet. The version-matched official wallet-delegated proof provider and browser ZK artifact provider are now installed, and an isolated client compiles and loads; no real-wallet proving or artifact-hosting test has passed.

The existing loopback proof server at `127.0.0.1:26300` returned version `8.1.0`. The cached `midnightntwrk/proof-server:8.1.0` image's `--help` does not list the `--network` flag shown in some older examples. A separate container started with `--network preprod` exited immediately; it was not used for any transaction. Do not assume that the old flag applies to this image.

The isolated Preprod demo deployment script's **read-only preflight** passed RPC chain identity (`Midnight Preprod`), indexer block response, local proof server version endpoint, compiled contract file checks, and the fixed valueless metadata/config hash. Its guarded `--execute` run has now completed without a pending action or active runner lock. The independently verified Preprod contract is `ef7cb50ea29a2ab3501dac80d3fa9f05f570294a2fc0107ad0fc5b76cefe3921`; its four registration slots were empty at verification.
